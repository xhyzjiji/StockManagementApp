# KB Doc Templates (four-piece + CLAUDE.md structure templates) v1.1

> Purpose: freeze the validated structure of high-recall KB docs into templates, so docs generated by
> kb-init-docs / kb-update-docs are structurally stable and useful to both humans and agents.
> Reference point: global-rule-creator's rule.template.md (same pattern).
> Structure and constraints validated by before/after adversarial evaluation on 4 real modules (iOS×2 / Android×2).
> Usage: when generating/updating a file, fill in the corresponding template's skeleton; `<...>` angle-bracket text is
> placeholder guidance — delete it once filled.
>
> **Canonical language = English.** Template skeletons (section headings + guidance) are written in English. Generated
> docs follow the kb-init / kb-update `--lang` flag: `--lang en` (or an English context under `--lang auto`) → keep the
> English headings; `--lang zh` (or a Chinese conversation under `--lang auto`) → translate the headings AND the body to
> Chinese. Keep a single language per doc — never mix (e.g. don't leave a Chinese heading in an English doc).
>
> General rules (apply to all files):
> 1. **Length budget = a pure upper bound, tiered by module size (S/M/L)**: the tiers and per-file line caps are owned
>    **solely** by `../../kb-docs-validator/references/kb-doc-budget-contract.md` (same mechanism as the rule quality
>    contract). **That contract is the source of truth; do not copy the numbers here** (avoids dual-source drift). Tiers:
>    M = baseline (30–149 source files), S = tighter, L = wider but prefer splitting into sub-module KBs. **There is no
>    floor** — content that says everything needed is complete; "padding lines to hit the budget" is a smell. Over the
>    upper bound = split into a sub-module KB. Small (S) modules may drop a whole inapplicable section with one line:
>    "N/A: logic lives in the impl layer, see <impl> KB".
> 2. **Language**: one consistent language per doc; pick the heading version that matches the doc's language (see the
>    Canonical language note above) — never mix English and Chinese headings in one doc.
> 3. **Code anchors**: when naming a class/method, give locating info (class name + relative path). **Spell symbols out in
>    full — no `{A,B}` brace/wildcard abbreviations** (they break literal search); trimmed example code **must not drop a
>    protocol's/interface's required members**, and every type name (including @objc aliases) must appear in full at least
>    once; prefer method-name anchors over line-number anchors (line numbers rot).
>    **Anchor ≠ transcription**: an anchor is `name + relative path + one line in your own words` —
>    NEVER a pasted source declaration block or copied `///` doc comment. The source file is the always-fresh SoT and
>    agents read it directly; a doc that mirrors source at ~1:1 compression saves zero reading cost and is guaranteed
>    to rot (audited: top oversize docs were 68–94% verbatim source transcription). What earns doc lines is what
>    source can't say: threading/ordering constraints, pitfalls, cross-file wiring, rationale.
> 4. **Diagrams no longer require a per-diagram prose restatement** (the restatement duplicates the L2
>    steps/tables — drop it): render the diagram where it renders (Lark/web). **But every class/method name appearing in a
>    diagram MUST appear in the body (L2 steps / tables; a class that only appears in a diagram is anchored in `CLAUDE.md`'s Key Classes)** — before removing/editing a diagram,
>    extract all its symbols and ensure the body covers 100% (**preserve symbols, not the prose restatement**; sequence-
>    diagram participants are high-density anchors — make sure they land in the body).
> 5. **Write the failure paths**: workflow/rule MUST cover failure/degradation/edge cases, not just the happy path.
> 6. **Freshness**: no dated changelog at the top of a doc; delete stale content instead of appending.
> 7. **"TBD" discipline**: allowed only on items someone will actually fill (prefer an owner); **forbidden** as empty
>    table rows, double-TBD rows, or TBD used to pad an empty section. For an empty section, pick one: delete / write
>    "None" / TBD + owner.
> 8. **Post-edit self-check**: for modules with docs/evals/, run the assertions after editing; on a "new vs old symbol
>    conflict" check the source first — **both may genuinely exist** (two gates at different layers) — and document both.
> 9. **Coverage completeness (don't write only the main pipeline)**: before generating, **enumerate ALL sub-feature-
>    domains of the module** (entry / growth / tracking / per-business-line / tools… everything that actually exists) and
>    cover each, not just the main chain; after generating, run the **key-class anchor self-check** — for each important
>    class from `kb_tool.py select-key-classes <root> --top N`, verify it is **anchored in some doc** (domain / interface /
>    workflow / architecture) with class name + relative path; add back any that were dropped. Restructuring / tightening
>    the budget may reorganize content but **must not drop important classes wholesale** (the dividing line between a
>    high-recall doc and a merely "clean" one).
> 10. **SSOT for rules**: a shared/common rule lives in exactly ONE place — the nearest common ancestor `rule.md`. A
>    child `docs/rule.md` MUST open with an **Inherited Rules** section linking its ancestor rule index, then write only
>    local differences / overrides — never restate an inherited scenario (the validator WARNs on `WHEN` / heading
>    overlap with an ancestor).
> 11. **SSOT for content (one fact, one file)**: each fact lives in exactly ONE file per the boundary table below.
>    In particular for the workflow ↔ architecture ↔ interface trio: **`workflow.md` owns runtime / temporal
>    step-by-step flows and call sequences** (it is the ONLY file that carries them); **`architecture.md` is static
>    structure only** (layers / deps / data ownership) and, where a runtime sequence is relevant, **links to
>    `workflow.md` instead of restating it**; **`interface.md` (Required zone) is the sole home of the external-
>    dependency inventory**. The same numbered call sequence MUST NOT appear in both `workflow.md` and
>    `architecture.md`, and the external-dependency list MUST NOT be duplicated in `architecture.md`.
> 12. **No `Class → Path` inventory (it's regenerable, not "moved to CLAUDE.md")**: do NOT tabulate a `Class | Path`
>    mapping in any doc — the old `workflow.md` `Implementation Anchors` (`Class | Path | Responsibility`) table was
>    removed for exactly this reason. A class's file path is navigation info that is cheaply **regenerable**: grep the
>    class name, or read `CLAUDE.md`'s Module Overview **directory tree**. `CLAUDE.md`'s Key Classes deliberately
>    carries only `Type | Kind | Description` (**no `Path` column**) and lists only the 5–15 most important classes —
>    it is a curated highlight, **not** a class→path index; long-tail classes are found by grep, not by lookup. So a
>    class→path fact has **no explicit home by design** (that is intentional, not a gap). Record a class in a doc only
>    when it carries a business fact worth a sentence (a contract / a `WHEN` / why it is load-bearing); a bare
>    class→path row is not that.

| File | Template | Core responsibility (boundary — don't bleed into each other) |
|---|---|---|
| CLAUDE.md | CLAUDE.template.md | Module entry map: overview + key classes + doc navigation |
| docs/domain.md | domain.template.md | Business terminology + core objects (**business only**; architecture moves to architecture.md) |
| docs/interface.md | interface.template.md | Boundary map — **Provided**: protocols / routes / events (the public contract); **Required**: network APIs the module calls + external dependencies (verbatim full route paths, never invented names) — the **sole home** of the external-dependency inventory (architecture.md must not duplicate it) |
| docs/workflow.md | workflow.template.md | Flows: human-readable summary layer + AI detail layer (two-tier) — the **sole owner** of runtime / temporal step-by-step flows and call sequences |
| docs/rule.md | rule.template.md | Constraints & conventions: each rule has a Why (production traceability) + a counter-example |
| docs/architecture.md | architecture.template.md | **Conditional standard piece**: create only when the module has real architecture (multiple layers / complex deps / clear data flow) — **static structure only**: layers / deps / data ownership; **defaults to including a layered-structure / dependency Mermaid diagram** (text-mirror rule: every diagram node also appears in the prose/table); **must NOT restate workflow.md's runtime step sequences (link them) nor re-inventory interface.md's external dependencies**; thin modules skip the file, structure overview goes in CLAUDE.md |

After generating the four-piece set, prompt to call `kb-evals-creator` to generate docs/evals/ (optional but recommended — the recall dashboard surfaces evals coverage).
